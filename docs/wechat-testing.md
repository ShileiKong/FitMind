# FitMind 微信手机本地版 · 0.3.8

这是无需电脑常驻、无需自建服务器的个人小程序。首次打开即可记录；饮水、饮食、目标、周计划、训练组、身体数据、记忆和对话都保存在这部手机。AI 单独联网调用 DeepSeek。电脑版继续使用原后端，两个版本不会自动同步。

## 手机开始使用

1. 扫描新版预览二维码，确认「我的 → 本地数据、AI 与提醒设置」顶部显示 **手机本地版 · 0.3.8**。已有本地数据会保留。
2. 手动记录和本地规则助手无需配置。可说“喝了300毫升水”“体重70公斤”，训练中可以说“这组30kg做了12次”。复杂饮食估算和制定计划需开启 AI。
3. 在该设置页填入个人 DeepSeek API Key，模型默认 `deepseek-flash`，点「保存 AI 设置」后「测试 AI 连接」。Key 只存本机，不进入安装包或数据备份。
4. 小程序管理员在微信公众平台「开发管理 → 开发设置 → 服务器域名」将 **https://api.deepseek.com** 添加为 **request 合法域名**。这只是允许访问模型供应商，不需要你部署服务器。遇到域名校验错误，应完成此配置；发布工程保持域名校验开启。
5. AI 生成的草案卡片明确标为「饮食目标」或「运动目标」，提供「查看详情」和「确认并应用」。确认后从设备今天生效并更新今日额度，停留在当前对话继续交流；详情页也可确认。饮食目标包括热量、三大营养素和饮水额度；运动目标保留每周训练星期，今天休息时显示计划已启用和下一次训练。

设置页「已配置」表示配置存在，不代表已经通过真实 API 调用。照片识别需保存个人 Key，并使用支持图片的 DeepSeek Flash 模型；默认 `deepseek-flash`，也支持 `deepseek-v4-flash` 和 `deepseek-v4-flash-vision-exp`。没有 Key 或使用其他模型时，照片入口会提示先配置，手动记录继续可用。

AI 只发送对话所需的资料、相关记录、计划和记忆；照片识别会发送你选中的照片及补充描述。思考内容不展示，回复以简短结果和保存回执为主。默认模型依据 [DeepSeek 官方接口](https://api-docs.deepseek.com/api/create-chat-completion/)；微信网络配置参见 [微信网络文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。

## 照片识别与键盘听写

- 点击输入框旁的照片按钮，选择「拍餐食 · 估算营养」或「拍营养表 · 按食用量计算」，再从相机或相册选择照片。识别结果先作为草稿展示，不会自动生成饮食记录。
- 餐食照片始终按估算处理，可补充或修改食物名称、份量说明与营养值；营养标签需核对每 100 g、每 100 ml 或每份的基准，并填写实际食用量。核对后点击确认保存，今日摄入才会更新。照片不能保证营养值准确。
- 取消选图会保留原草稿；拒绝相机或相册权限时会提示，可到微信权限设置中开启或继续手动输入。识别失败或被微信中断时可回前台重试，确认保存之前不会记账。
- 点击语音按钮会聚焦输入框，提示使用手机键盘上的麦克风听写。听写文字和普通输入一样，可修改后再发送；小程序不请求录音权限、不录音、不上传音频，也不调用 ASR。键盘听写由手机系统或输入法提供，不承诺每种键盘都有麦克风。
- iPhone 键盘没有麦克风时，检查「设置 → 通用 → 键盘 → 启用听写」和当前输入法的键盘设置；仍不可用时可以直接键入。不要把「手机键盘听写」理解为小程序内置语音识别。

照片单张上限 **5 MiB**。本地最多缓存 **30 张、合计 40 MiB**，超过任一上限时清理最旧照片缓存；已确认保存的饮食记录和营养值保留。原图不会进入业务 JSON 备份，照片仅备份元数据。导入备份或重置本地数据会清理照片缓存，AI Key 保留。

## 新版教练体验

- 「我的 → 切换皮肤」提供原版科技黑绿和「DeepSeek · 蓝鲸」。蓝鲸皮肤采用浅蓝白与蓝紫配色，首页与教练头像显示角色形象。选择立即应用并保存在本机，退出重开仍保留；切换、清空业务数据或导入备份不会改变这个外观偏好。
- 蓝鲸皮肤的教练名为「大肥鱼」，首页、输入框、回复预览和完整对话同步使用这个名字。
- 今日页的饮水、热量、碳水、蛋白质和脂肪卡片都可点击「查看来源」，查看所选日期的摄入记录、每项贡献和占已知摄入小计的比例。营养标签、估算和待补项分别标明；待补项不计入已知小计。点一条来源记录即可更正，返回后明细和今日余额更新。
- 在今日、计划、训练或我的页点击底部输入框，上方展开最近一轮简短回复、保存回执、错误和草案入口。发送后可直接查看结果，长回复可点「展开详情」在该区域内滚动阅读；拖动主页面收起，拖动回复区阅读则保持展开。进入完整对话自动定位最新消息，向上翻阅历史时不会被定时刷新拉回底部。收起不会清除未发送文字，完整对话入口仍可用。
- 饮食不清楚热量时可以说“你来估算”。教练优先利用已经提供的食物、份数、重量或体积，采用常见份量并说明假设，可事后更正。“两份一共500g”按合计500g，“每份500g、两份”按1000g。记录仍显示估算，不代表营养值精确。
- 今日页「和教练一起设置」进入首次引导：身高体重、性别、目标、力量训练意愿、运动时间、限制和器械。已有体重可带入核对；性别可不透露，时间和限制可跳过。每步答案逐步保存，退出后可从「我的 → 教练资料」继续，也能修改。
- 核对资料后保存，接入 AI 可生成饮食与运动目标草案，在卡片上即可明确确认并应用到今日。已应用的卡片显示状态，避免重复启用；被修订的旧卡片需先查看最新内容。没有 Key 时可以先完成资料，模型失败也不会丢失已保存资料；查看回执后恢复原消息。

## 自然日与跨天记录

每次对话先读取手机当前时间和用户时区，按日期读取当天账本。新一天的热量、碳水、蛋白质、脂肪和饮水从当天实际记录重新累计，不把昨天剩余或超出的额度带到今天；已确认每日目标继续沿用，历史记录保留。旧对话会带上原始日期，昨日说的“今天”不会当成当前日期。

跨午夜恢复失败消息、重试已保存记录或离线补记时，记录仍按原采集日期归属，成功回执不会重复保存。明确说“补记昨天”的输入只修改昨天的数据。

验收时在今日记录一份早餐，再问“今天已吃多少、还剩多少、下一餐怎么吃”，应按今日来源页的记录回答。次日重新进入或继续对话时核对当天日期，前一天食品不应出现在今日来源页；不要为测试清空历史数据。

## 0.3.8 对话与输入验收

- 对话说「根据我的资料设置每日饮食目标」：生成含热量、碳水、蛋白质、脂肪和饮水的草案卡片；点「确认并应用」，留在当前对话，今日额度立即更新。只设置饮水等单项目标仍受支持。
- 先记录早餐和午餐，再问「晚餐吃什么」：每次模型回复前读取当日全部真实饮食记录、已生效目标和剩余额度，刚保存的同轮记录也会计入。建议不自动记成已吃。部分未知以暂估额度标明，未设目标不虚构余额。
- 单次网络请求最多120秒，多轮处理预算360秒；五轮工具后仍有一次纯文本收尾机会。输出过长或微信网络中断有独立提示，可恢复原消息，已有成功回执不重复保存。请在小程序前台测试。
- 底部预览可展开并内滚动查看完整回复与卡片；完整对话打开即到最新消息，阅读旧消息时保持位置。
- 配置 Flash 和 Key 后，识别餐食照片和清晰营养标签，编辑份量并确认保存；识别、取消和失败过程均不增加记录。检查已保存记录只新增一次。
- 点击语音按钮后使用键盘麦克风听写，修改文字，发送前确认无新记录，发送后核对回执。实际手机键盘、相机/相册权限和真实 DeepSeek 调用需本人验收。

## 重新测试首次引导

进入「我的 → 本地数据、AI 与提醒设置 → 本地数据与备份」。

- 「重新开始首次引导」：确认后重置教练资料和引导进度，直接进入引导；保留已有记录、目标、计划、训练、对话、提醒设置和 AI Key，清理照片缓存。已有身体记录中的体重仍可带入核对。
- 「清空本地数据」：确认后删除全部业务记录、目标、计划、训练、对话、记忆、个人资料和照片缓存，回到首页重新设置。保留 AI Key 和已经导出的备份文件。删除无法撤销，先导出备份再测试。

取消弹窗不会修改数据；正在保存或等待 AI 回复时暂不能重置。清空会使旧表单和待处理输入失效，退出重开也保持空白状态。

## 备份与电脑版迁移

「本地数据与备份 → 导出并保存备份」生成 JSON 文件，使用微信文件分享保存到自己的文件传输助手等位置。业务备份中的照片仅保留元数据，不含原图或模型 Key。导入时，从微信聊天文件选择该 JSON，核对后点击「确认导入」。导入会替换当前数据并清理本地照片缓存，应先备份当前手机数据。模型 Key 保留，旧待处理输入和表单缓存失效。

如需从电脑版迁移，在自己的电脑版工程中导出业务数据，再将 JSON 文件保存到微信聊天并从小程序设置导入：

```powershell
node scripts/export-local-data.mjs --database data/fitmind.sqlite --out data/phone-backup.json
```

脚本不会修改原数据库，也不读取模型配置或访问令牌；图片文件不会随业务备份迁移。手机数据没有云同步；微信清理小程序数据或更换手机后，需要使用备份恢复。存储失败不会假装保存成功。

## 提醒与当前能力

保存前一晚的提醒时间后，到点进入小程序，首页显示明日详细计划入口。**微信关闭小程序后的定时手机推送需要服务器，本地版不发送。** 本地照片识别复用 DeepSeek Key；语音输入使用手机键盘听写，未接入小程序内置录音转写。

每次打开、刷新、发送消息都会读取设备时间，按设定时区计算自然日。旧消息重试使用原采集日期和原训练会话，不能移到第二天或再次记账。AI 超时后查看回执并恢复原消息，不要重新发一条相同记录。

## Windows 开发者工具和体验版

使用自己的小程序 AppID，导入构建输出 `apps/miniprogram/dist`，或解压公开 ZIP 后导入其中的 `miniprogram` 目录。普通小程序工程，不启用云开发模板，不需要构建 npm。源码工程运行：

```powershell
npm ci
npm run export:miniprogram
npm run package:miniprogram -- --out data/releases/FitMind-微信体验版.zip
```

源码构建输出 `apps/miniprogram/dist`。公开 ZIP 只含小程序代码、图标和本说明，不含 Key、个人数据库或备份。新版预览二维码文件名为 `exports/微信预览二维码-0.3.8.png`。

预览码用于开发者扫码自测；长期体验需在微信公众平台「版本管理」将开发版本 **0.3.8** 设为体验版。预览/开发上传不等于公开发布，手机实际验收需本人扫码完成。参考 [微信协同发布](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)。

## 验收流程

- 关闭电脑后端，在手机新增饮水、标签食品、估算食品、体重，再打开确认保留。
- 从「我的」进入切换皮肤，应用蓝鲸；核对首页、底部聊天框、目标卡片和计划页同步变色，重开仍为蓝鲸，再切回科技黑绿。确认原有记录和 AI 设置保留。
- 点击首页输入框，发送“喝了300毫升水”，直接看到已保存回执；拖动主页面收起，再点输入框仍可看到回复。
- 首次引导填写部分资料后退出，回来继续；修改力量训练意愿，保存后核对。已有资料、目标和计划不会被引导自动激活或取消。
- 在设置页取消一次清空，确认记录保留；再确认清空，检查首页首次引导重新出现、记录归零、AI 仍已配置，退出重开后结果保持。
- 目标剩余额度正确；部分营养未知时，大号数字先按已记录的营养小计显示“约”的暂算余额，并提示“待补部分未计入”。补全记录后自动更新。原始未知营养保留为空，没有目标时仍提示设置目标。
- 分别点击饮水、热量和三大营养素卡片，核对来源名称、摄入量、估算或标签标识和已知小计占比。点食物更正后返回，检查明细刷新；跨自然日后已打开的明细仍保持原日期，再回今日查看新一天。两套皮肤均可使用，大肥鱼名称只随蓝鲸皮肤展示。
- 对话生成饮食与运动目标，检查两类卡片各有查看详情和确认按钮。确认后回到今日，饮食额度立即更新；运动计划从今天启用，保留每周星期。重复打开对话显示「已应用」；修订草案后旧卡片先要求查看详情。
- 创建周期周计划并确认，详情先显示日期范围和每周安排；差异和实际日期仍可展开。
- 开始训练，录实际重量/次数，查看下组建议；结束后在历史里查看、更正或撤销。
- 配置 AI 后，对话记录、制定草案、查询历史、修订/删除记忆；说“不要确认”不能激活草案。
- 照片入口分别测试餐食和营养标签；核对编辑后的份量与营养值，确认保存前无记录，保存后额度更新。取消选图和拒绝权限后原草稿保留；真实供应商识别失败、微信后台中断后可重试。
- 手机语音按钮唤起输入框，使用系统或输入法听写，发送前可修改且无记录；检查缺少键盘麦克风时可继续手动输入。
- 导出备份、新增数据、导入原备份，确认替换、旧输入和照片缓存清理，Key 保留；再启动后仍一致。核对备份没有原图，缓存清理不删除已保存的饮食记录。

本次开发验证使用合成图片数据、模型响应和微信平台回调，覆盖解析校验、失败重试、份量核对、确认保存边界、缓存清理及键盘听写引导；没有据此宣称真实供应商或真机权限已经通过。真实 DeepSeek 照片与文字调用、iPhone/其他手机键盘、相机与相册权限、手指拖动和微信后台中断需本人扫码验收，营养准确性也需人工核对。
